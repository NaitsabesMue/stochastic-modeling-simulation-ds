\begin{frame}{Candidate 2: one daily level, many interval counts}
  \small
  For each regular working day $d$:
  \begin{enumerate}
    \item Draw one daily demand multiplier $G_d$. A value above 1 means a busier day; a value below 1 means a quieter day.
    \item Let $s$ denote one 15-minute slot and let $b(s)$ be the period containing that slot. The fitted baseline mean $\widehat m_{b(s)}$ comes from Candidate~1.
    \item Generate a separate arrival count for every slot:
      \[
        N_{d,s}\mid G_d
          \sim\operatorname{Poisson}\!\left(G_d\widehat m_{b(s)}\right).
      \]
  \end{enumerate}

  \textbf{Example:} At 09:30, $b(s)$ is the morning peak and $\widehat m_{b(s)}=39.9$. If $G_d=1.10$, the Poisson mean for that slot is $1.10\times39.9=43.9$.
\end{frame}

\begin{frame}{Fit the amount of day-to-day variation}
  \small
  Let the total arrivals on day $d$ be
  \[
    T_d=\sum_{s=1}^{96}N_{d,s},
    \qquad
    M=\sum_{s=1}^{96}\widehat m_{b(s)}=1{,}780.5.
  \]
  If the slot counts are conditionally independent, their sum satisfies
  \[
    T_d\mid G_d\sim\operatorname{Poisson}(G_dM).
  \]
  Set $\mathbb E[G_d]=1$ and $\operatorname{Var}(G_d)=\alpha$. Then
  \[
    \mathbb E[T_d]=M,
    \qquad
    \operatorname{Var}(T_d)=\underbrace{M}_{\text{Poisson variation}}
      +\underbrace{\alpha M^2}_{\text{variation between days}}.
  \]
  The ten training totals have sample mean $1{,}780.5$ and sample variance $59{,}632.7$. Matching the model variance to the sample variance gives
  \[
    \widehat\alpha
      =\frac{59{,}632.7-1{,}780.5}{1{,}780.5^2}
      =0.01825.
  \]
\end{frame}

\begin{frame}{Choose a distribution that we can simulate}
  We need a positive multiplier with mean 1 and variance $\widehat\alpha$. For
  \[
    G_d\sim\operatorname{Gamma}(k,\theta),
  \]
  using the shape--scale convention,
  \[
    \mathbb E[G_d]=k\theta,
    \qquad
    \operatorname{Var}(G_d)=k\theta^2.
  \]
  Choosing
  \[
    \theta=\widehat\alpha=0.01825,
    \qquad
    k=\frac{1}{\widehat\alpha}=54.8
  \]
  gives the required mean and variance. The standard deviation of $G_d$ is
  \[
    \sqrt{0.01825}=0.135,
  \]
  so day-level demand varies by about $13.5\%$ of its mean per standard deviation. 
\end{frame}

\begin{frame}{What the simulator must record}
  \small
  \begin{tabular}{@{}ll@{}}
    \toprule
    Recorded value & What it lets us calculate\\
    \midrule
    arrival time & demand chronology\\
    service-start time & waiting time\\
    departure time & time in system\\
    assigned agent & workload of each agent\\
    queue length after each event & queue length over time\\
    number of busy agents after each event & agent occupancy over time\\
    \bottomrule
  \end{tabular}
  \par
  \vspace{0.55em}
  \textbf{Summarize distributions, not only averages:}
  \begin{itemize}
    \item \textbf{Waiting time across customers:} mean, median, quantiles and fraction who wait.
    \item \textbf{Queue length over time:} mean, quantiles, maximum and fraction of time the queue is non-empty.
    \item \textbf{Agent occupancy over time:} mean fraction of agents busy and fraction of time exactly $0,1,\ldots,c$ agents are busy.
  \end{itemize}
\end{frame}

\begin{frame}{Check the implementation before the model}
  \begin{itemize}
    \item Run both five-customer examples, then verify by hand that the code assigns the same agents, start times, waits and departure times.
    \item Check every customer: $B_i\ge A_i$, $D_i=B_i+S_i$, and $W_i\ge0$.
    \item Increase service duration: waits should not decrease for the same arrivals.
    \item Run the same seed twice: the result should be identical.
  \end{itemize}
  \vspace{0.5em}
  Passing these checks supports the implementation. It does not show that the implementation is correct.
\end{frame}

\begin{frame}[fragile]{Make the checks repeatable with unit tests}
  \footnotesize
  A \textbf{unit test} is a small automatic check of one behaviour whose
  correct answer is already known.

  \vspace{0.4em}
\begin{verbatim}
import math

def test_two_agents():
    result = simulate_queue(
        arrivals=[0.0, 1.0, 2.5, 2.7, 3.0],
        services=[2.0, 2.0, 1.0, 2.5, 1.5],
        number_of_agents=2,
    )
    assert result["agent"] == [1, 2, 1, 2, 1]
    expected_waits = [0.0, 0.0, 0.0, 0.3, 0.5]
    pairs = zip(result["wait"], expected_waits)
    for got, expected in pairs:
        assert math.isclose(got, expected, abs_tol=1e-9)
\end{verbatim}

  \vspace{0.25em}
  Run the tests after every code change; add a test whenever a bug is found.
\end{frame}

  \raggedright
  \vspace{0.9em}
  \begin{itemize}
    \item The first $M$: independent exponential times between arrivals, equivalently a constant-rate Poisson arrival process.
    \item The second $M$: independent exponential service times with mean $1/\mu$.
    \item The $c$: the number of agents working in parallel.
    \item The waiting room is unlimited; service is FIFO; callers do not abandon.
  \end{itemize}

  \vspace{0.3em}
  This infinite-horizon model is a theoretical reference for the finite morning simulation.
\end{frame}

\begin{frame}{The reference model gives a stability test}
  \small
  When a queue is present, all $c$ agents are busy. Their combined service
  capacity is $c\mu$ calls per minute, while calls arrive at rate $\lambda$.
  Define
  \[
    \rho=\frac{\lambda}{c\mu}.
  \]
  For the infinite-horizon $M/M/c$ model, a stationary queue exists exactly when
  \[
    \rho<1 \qquad\text{or, equivalently,}\qquad \lambda<c\mu.
  \]

  \vspace{0.7em}
  \begin{itemize}
    \item If $\rho\ge 1$, arrivals match or exceed the maximum average service rate, so the queue cannot settle into a stationary distribution.
    \item If $\rho<1$, the system has enough average capacity, but random arrival and service variation can still create long waits.
  \end{itemize}
\end{frame}

\begin{frame}{Apply the stability test to the morning scenario}
  \small
  For an average-demand morning,
  $\lambda=39.9/15=2.66$ calls/min and $\mu=1/6$ calls/min per agent.

  \vspace{0.7em}
  \centering
  \begin{tabular}{@{}crrc@{}}
    \toprule
    Agents $c$ & Capacity $c\mu$ & $\rho$ & Theoretical diagnosis\\
    \midrule
    15 & 2.500 & 1.064 & no stationary queue\\
    16 & 2.667 & 0.998 & stable, almost no spare capacity\\
    17 & 2.833 & 0.939 & stable, some spare capacity\\
    \bottomrule
  \end{tabular}

  \raggedright
  \vspace{0.8em}
  Since $\lambda/\mu=15.96$, 16 is the smallest stable integer for an
  average-demand morning; 17 is the first level with some buffer. These are
  candidate staffing levels, not yet a waiting-time conclusion. On a simulated
  morning, $\lambda$ is multiplied by $G_d$.
\end{frame}

\begin{frame}{First simulate around the capacity boundary}
  The theoretical model tells us where to look. Simulate the same arrival and
  service paths with:
  \[
    15\text{ agents}\qquad 16\text{ agents}\qquad 17\text{ agents}.
  \]
  \begin{itemize}
    \item Does a queue remain at 11:00?
    \item How does the queue-length distribution change?
    \item How does the waiting-time distribution change?
    \item How often are all agents busy?
  \end{itemize}
  \vspace{0.4em}
  This locates the transition from insufficient capacity to useful spare
  capacity for the stated scenario.
\end{frame}

\begin{frame}{Then measure the effect of one additional agent}
  After locating the critical range, compare 16 and 17 agents using identical
  arrivals and service requirements.
  \vspace{0.5em}

  Report the change in:
  \begin{itemize}
    \item mean, median and upper quantiles of waiting time;
    \item fraction of callers who wait;
